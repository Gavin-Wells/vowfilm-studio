# 账号、权限与可配置计费模型

## 边界与领域

平台用户拥有项目及其素材。平台管理员管理账号、角色、引擎与价格；创作者只能创作自己的项目；只读成员只能读取自己的项目；财务人员管理充值与账本，但不能读取别人的影片。旧项目不公开，首次管理员初始化时归属管理员。账号、项目元数据与财务数据存入可切换的 SQLite/PostgreSQL 仓库，媒体保留磁盘结构。

登录采用邮箱与密码、随机服务端会话、HttpOnly/SameSite cookie。首次管理员需要本机初始化密钥；普通注册不能指定角色。提供修改密码、退出、退出全部设备、一次性恢复码找回密码。恢复码只展示一次，数据库只保存摘要；未接入邮件，因此邮箱是登录名，不表示已验证邮箱所有权。

## 数学模型

所有积分用整数“微积分”保存，1 积分 = 1000 微积分；不把积分视为人民币或第三方 API 成本。动作集合 A = {plan, review, generate, shot, render}。场景集合 S = {wedding, family, anniversary, commerce}。

价格规则 R_v = (action, unit, base, rate, minimum, sceneFactorBps)，版本 v 发布后不再修改。单价与起步价单位为微积分；场景系数以万分比保存，10000 表示 1 倍。

- call：一次用户确认的业务调用，q = 1。请求重试使用同一个幂等键，不是新的调用。
- task：一个完整业务任务，q = 1。一键生成包括其内部导演、镜头、配乐与合成，不重复叠加计费；单独编排、重做或合成是另一个任务。
- second：整片动作按目标成片秒数；局部重做按该镜头的生成秒数。
- shot：整片动作按已有镜头数或后端计算的预计镜头数；局部重做 q = 1。

冻结价 C = max(minimum, ceil((base + rate × q) × sceneFactorBps / 10000))。

所有运算有整数上限检查。报价绑定用户、项目内容摘要、动作、镜头、规则快照、数量和有效期（10 分钟）。调价不修改报价或旧账单；项目内容变化需重新报价。前端模拟器仅供试算，收费由后端同一计算函数决定。

账户总余额 B，可用余额 A，冻结余额 H，累计已消费 D：A = B − H；B ≥ H ≥ 0。

- 充值：B' = B + x，H' = H；必须有管理员/财务操作者、原因与唯一凭据号。
- 预授权：要求 A ≥ C；H' = H + C。
- 成功结算：B' = B − C，H' = H − C，D' = D + C。
- 失败/取消释放：B' = B，H' = H − C。

一个任务只允许从 held 进入 settled 或 released 一次。余额变动与流水在所选数据库的同一事务内提交；流水记录余额/冻结的变化与变后值。独立只读视图不收费，取消不收费。失败或取消不收平台积分，即使第三方已产生费用；这部分成本由平台承担。这个默认策略明确而可验证，未来可扩展按实际完成量结算，不能直接更改历史记录。

## 状态与幂等

quote → held → settled / released。幂等键按用户唯一，同时绑定报价；重复提交相同键返回原结果，键绑定不同报价则拒绝。余额不足、权限不足、过期或内容不匹配不会启动任务。启动失败立即释放。进程恢复时未完成的冻结单释放，项目暂停，用户重新确认报价后继续，保留云端任务 ID；不自动进行无报价的付费恢复。

SQLite 使用事务、外键、WAL 和 FULL 同步。价格版本只追加，充值凭据唯一。项目快照与账本不处于同一事务，因此重启采取保守释放政策，可能减收，不向用户重复收费。当前仅支持单个 Go 实例；多实例需要把项目、作业与账本统一到数据库并增加作业队列/事务 outbox。

## 场景语义

- 婚礼：入场开场、爱情回顾、暖场循环；保留现场接话与片尾约束。
- 家族传承：家族口述史、长辈纪念、家风传承；年代与亲缘关系依据资料，不编造真实家史。
- 爱情纪念：周年纪念、恋爱回忆、异地寄语；不强加婚礼仪式和礼服。
- 电商：商品展示、使用演示、品牌故事；主体是商品，保持外观/包装，卖点与参数仅来自资料，不编造销量、背书或功效；默认短时长、竖屏。

场景进入校验、表单、导演方案、分镜、素材说明、音乐及片尾处理。兼容旧 bride/groom 造型字段，但非婚礼含义为主角/其他人物，电商含义为商品/环境，无人物时明确为空场景。

## 后续收款适配

本次实现可用积分账本和人工充值核验，不模拟支付成功。真实收款独立于任务计费：订单用最小货币单位保存金额，服务端验签后按唯一支付凭据充值；需要金额/币种匹配、防重放、订单超时、退款与对账。不应直接信任客户端支付结果。订阅、套餐、赠送额度、税务发票可在订单/权益层扩展，不更改底层冻结与结算不变量。
