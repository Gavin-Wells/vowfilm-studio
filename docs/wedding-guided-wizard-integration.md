三个需要提前处理的具体兼容问题：

1. 上游采集卡默认 90 秒；当前婚礼校验仅允许 60/120/180/240 秒。向导需要支持 90 秒等目标时长，并分别保存目标片长、实际旁白时长和确认后的成片总帧数。
2. 当前婚礼渲染会去掉源片声音，再加入背景音乐；旁白文本字段不会自动形成独立配音。必须新增旁白音轨、语义时间点和混音处理。
3. 当前 `render()` 会再次调用 `layout()`，并可能生成或替换配乐。向导渲染必须消费已确认的时间表与混音；否则渲染时会改变已审核内容。

**14 步如何落在产品中**

建议在婚礼创建入口提供“真实故事定制”，默认用途为爱情回顾，可按现场要求调整。工程页用五个分组组织阶段：故事、旁白、画面、配乐、交付；始终显示实际步骤编号、当前材料、下一操作和确认人。每个阶段只突出当前需要执行的动作，移动端用折叠阶段列表。

| 上游步骤 | 系统内交付 | 推进依据 |
| --- | --- | --- |
| 1 | 五幕故事表、事实清单、人物照片对应关系、缺项提示 | 制作方核对资料；未发生、记不清、不想呈现分别记录 |
| 2–3 | 当前文案版本、可复制写作包、修改记录 | 先制作方审稿，再记录新人确认该版本 |
| 4–5 | 同段文字的音色样本、选定设置、完整旁白及时间点 | 音色选择和完整试听分别确认 |
| 6 | 依据旁白设计的分镜、事实来源、人物时期及参考图安排 | 制作方确认本版分镜 |
| 7–8 | 少量关键试图、剩余首帧、每镜选版和整套检查 | 先确定试图，再审核全部选用图片 |
| 9 | 每镜首帧及视频词 ZIP、逐镜生成或回传视频 | 完整动作及相邻剪点通过审核 |
| 10–12 | 音乐候选、代表片段混音、全长混音 | 样本和完整声音分别确认，绑定同一套源文件与参数 |
| 13–14 | 带字幕预览、正式 MP4、SRT、剪辑表、素材清单 | 制作方通过预览及正式导出后，再记录新人最终验收 |

编号与确认职责依据上游 [14 步定义](https://github.com/aaronyi97/wedding-video-guided-wizard/blob/4344397a5f9800c0a5550a83c8358f88afea9b03/SKILL.md)。新人端首版可以使用采集卡和可转发的文案/成片，由制作方录入具体确认反馈；后续再增加受限分享链接。客户无需安装 Skill。

交互采用进度显示、当前步骤说明、字段旁错误和明确的保存反馈；这是此次 `ui-ux-pro-max` 对多步骤表单检索中匹配的建议。沿用系统现有视觉组件。

**建议的数据与执行结构**

在 `Project` 下增加可选的 `WeddingWorkflow`。现有 `projects.body` 保存完整 JSON，首版这些附加字段可以随项目快照入库；若后续需要独立审批查询或多实例并发，再引入专表、迁移和行版本检查。

| 对象 | 建议字段 | 用途 |
| --- | --- | --- |
| `WeddingWorkflow` | `schemaVersion`、`policyVersion`、`currentStep`、`steps`、`acceptedAt` | 保存业务流程；与生成任务状态分开 |
| `StoryIntake` / `Fact` | 原始回答、人物、年代、地点、事件、来源、是否确认、是否呈现 | 文案与分镜引用事实 ID；缺项不自动变成虚构经历 |
| `ScriptVersion` | `id`、正文、`factIds`、`sha256`、历史版本 | 审核、配音与字幕共享同一确认稿 |
| `Narration` | 选定音色、语速、方向、脚本版本、音频产物、实际时长、`cues` | 时间点来自实际音频；支持服务时间戳或人工校正的字幕文件 |
| `Artifact` | 类型、`shotId`、文件、MIME、大小、SHA-256、版本、依赖版本 | 区分人物参考、首帧、视频、旁白、音乐、混音与成片 |
| `StepReceipt` | 阶段、产物集合指纹、审核结果、记录人、确认方、反馈依据、时间 | 确认绑定具体版本；技术检测与人的确认独立记录 |
| `Timeline` | 总帧数、镜头净起止帧、源片入出点、转场余量、字幕时间段 | 渲染可重复消费同一确认结果 |

镜头增加 `factIds`、`narrationCueIds`、`firstFrameArtifactId`、`selectedVideoArtifactId`。人物身份参考和镜头首帧具有不同职责；阶段产物不应全部塞入现有 `Assets`，否则会触发数量限制，还会被误当成每镜都需要的参考图。

阶段可使用 `not_started / awaiting_materials / awaiting_confirmation / confirmed / needs_review`。模型任务继续使用现有运行状态；任务执行完毕只表示产物就绪。正式交付完成由第 14 步的制作方核对与新人验收决定。

审批记录中的记录人来自登录会话。“新人确认”可由制作方转述，但需同时保存转述身份和具体反馈，不能把任意客户端传入的 `couple` 当作独立认证身份。确认之前重新核对产物版本，过期页面提交确认时返回版本冲突。

接口建议在项目下新增 `GET /workflow`、`PATCH /intake`、`POST /workflow/steps/{n}/run`、`POST /workflow/steps/{n}/approve`、`POST /workflow/reopen`、`POST /artifacts` 和按版本下载的文件包入口。路径均为建议，尚未实现。上传按产物类型限制容量并探测真实媒体；文件所属项目与镜号必须校验。

现有 `/plan`、`/generate`、`/render`、`/review`、单镜重做和项目设置修改入口，也需要识别向导模式并校验依赖，防止绕过审核。特别是现有 `/review` 是模型修订字幕，不能直接充当人工审批接口。

**返工和计费处理**

| 修改 | 需要重新审核/生成 | 可保留的成果 |
| --- | --- | --- |
| S04 首帧更换，剧情和时长不变 | S04 图片和视频、相邻剪点、完整预览、正式交付 | 其他镜头、原文案、旁白和已确认混音 |
| 文案含义改变 | 文案双方确认、相关旁白、分镜语义与后续受影响产物 | 经检查仍适用的原始照片和镜头 |
| 旁白时长改变 | 语义时间点、镜头时长/剪点、字幕、配乐安排、混音与成片 | 不受剧情和时长影响的素材文件 |
| 背景音乐更换 | 音乐选择、片段及全长混音、预览与交付 | 文案、旁白、图片及视频；必要时复查剪点 |

上游的 `reopen` 支持指定受影响步骤，但受影响范围需要调用方提供。系统应建立镜头和产物的依赖关系，计算默认返工范围，并保留旧版本和确认历史。单镜修改不应通过现有全项目 `PATCH` 清空成果。

付费动作按阶段作为短任务提交，继续使用报价、冻结、幂等和成功/失败结算。等待新人或外部素材期间只保存待办，不长时间占用运行任务或冻结整单额度。确认、资料保存、外部产物登记本身不冒充模型生成费用。

新动作需要在报价及启动前检查阶段依赖。向导报价指纹建议绑定当前阶段、输入产物版本、生成参数与价格版本；当前报价使用整个项目 JSON 的摘要，审批记录或无关事件变化也会使其失效。视频仍保留任务 ID、尝试次数及累计生成预算，返工不能清零已发生用量。旁白实际时长、成片帧数与请求生成秒数分别记录，并在报价中明确使用哪种计量。

**代码组织与实施顺序**

建议新增 `server/internal/wedding/`，存放版本化阶段规则、提示词、文件包逻辑和依赖校验；领域类型放 `server/internal/domain/`，应用编排和 HTTP 路由放 `server/internal/studio/`。新增前端向导与采集组件，接入 `app/new/page.tsx` 和现有项目工作台。

提示词版本管理可以参考本系统 [advertising/prompt.go](../server/internal/advertising/prompt.go) 的嵌入与内容摘要。婚礼每次调用只加载当前阶段所需规则及本单数据，产物保存规则版本；宿主对话操作、命令行路径和示例占位符需要转换成系统接口约定。

| 顺序 | 范围 | 可评审的结果 |
| --- | --- | --- |
| 1：故事与审核基础 | 模式入口、90 秒等规格、结构化故事、事实引用、14 步状态结构、文案版本及第 1–3 步、写作包 | 完成一份真实故事的采集和双层文案确认；重启可续做，旧版本无法误确认 |
| 2：完整素材回传流程 | 第 4–14 步界面、旁白及时间点导入、按声音分镜、首帧/视频回传、逐镜 ZIP、试听、混音、字幕、预览与交付 | 外部生成的素材能在本系统经过审核，完成一单带旁白字幕的影片；S04 可独立返工 |
| 3：增加阶段自动执行 | 配音适配、按选定首帧的视频适配、音乐样本、阶段计费 | 在原有审核流程中减少手动搬运，失败可恢复且不重复提交任务 |

第三阶段复用已配置的视频和配乐服务，按实际供应商能力验证接口；文字可接现有 LLM。配音需单独确认适配能力与配置。首帧锁定目前尚未在本系统该路径中得到验证，在确认接口支持前使用外部生成及视频回传。上游推荐的具体型号不作为系统固定依赖。

首版的重点验收用例应覆盖：未确认文案时阻止分镜或付费生成；文件换版后旧确认失效；制作方通过正式片后仍待新人验收；旁白时间轴在重复渲染后不改变；单镜换图保留无关成果；外部视频可按镜号回传；租户间不能读取或确认对方产物；阶段重试复用任务和账单。现有模板、Agent 和电商分支需跑相应回归检查。
