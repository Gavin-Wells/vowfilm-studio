# 模板创作与 Agent 创作

新建页面提供模板、Agent 和带货快创三个入口。模板包含固定镜头方案与婚礼故事流程两类；Agent 从用户资料重新编排故事；带货快创使用电商专用分镜与生成分组。

## 婚礼故事模板：把日子写成我们

该模板使用 `creationMode=template`、`templateId=wedding-story-guided` 和目录中的 `engine=wedding-guided`，默认 90 秒、16:9。它固定原版制作方法，镜头按实际旁白时间点生成，不套用十二镜结构，也不走下文固定模板的本地编排分支。

用户填写故事后可确认一次报价自动成片，也可使用 14 步逐步制作、回传素材和记录确认。原版 Prompt、采集卡、文件摘要、依赖与验证边界见 [婚礼故事模板](wedding-story-template.md)。电商流程见 [电商广告](advertising-prompts.md)。

## 婚庆模板：跨越时光的誓约（v3）

首个婚庆模板参考用户提供的 76 秒横屏婚前微电影，抽取出古风初见、荷塘同游、中式誓约、复古重逢、现代相伴和当代婚礼六个叙事段落。v3 是 60 秒、16:9、12 个固定镜头，使用 144 BPM 的高能量预告节奏；24fps 编辑时间轴由 `editFrames` 明确给出，片尾镜头保留最后 72 帧（三秒）稳定亮相。原片在选择区直接播放，并标记为“参考效果预览 · 原作者作品”；模板不会复制原片人物、字幕或音乐。

v3 的节奏基于 144 BPM。镜头以侧跟、半环绕、手势匹配、画框/荷叶/红绸遮挡和步伐落拍推进，第一拍就进入动作，避免整段慢推或静止摆拍。章节边的可视转场写在每个镜头的 `transition`、`transitionReason` 中：第 2、4、6、8、10 镜分别使用 `dipwhite`、`dissolve`、`dipwhite`、`wipeleft`、`slideleft`，其中闪白不超过两次、叠化不超过一次，片尾使用 `cut`。转场由渲染器真实执行；它们不是只供文案展示的标签。

音乐按章节设计：模板的 `bpm` 与 `musicDirection` 给出全曲方向，每个 `chapters[].music` 给出该章的配器、能量、第一拍事件与交给下一章的衔接。v3 的六段依次是：0–10 秒古风拨弦直接起拍；10–20 秒节奏组与主旋律完整陈述，18–20 秒上行；20 秒强落点进入中式喜庆高潮（对应誓约章节的闪白）；30–40 秒同速换成摇摆律动的对比桥段（对应复古段落）；40 秒主题回归；50 秒第二次落点加入铜管，57 秒收束只留长音（对应最后三秒留画）。整段由 Seed Audio 1.0 按这份分段设计一次生成（见 `docs/workflow.md`）。生成失败时使用本地器乐 fallback，并在成片元数据中如实记录来源；不会伪称使用了外部曲目。

视频任务提交前，后端会在每个镜头提示词顶部生成固定的 `@图片N` 素材清单，编号严格沿用实际提交顺序，并在末尾列出场景、人物、服装和道具的用途。没有真实音频参考时，提示词明确写“未提交音频参考”，不生成虚假的 `@音频N`。模板镜头按顺序提交；无真人参考素材的虚构项目会在第一个完成镜头后固定一张身份锚点，后续镜头复用同一身份锚点并只按章节切换服装。

模板会保存 `templateId` 和 `templateVersion`。新项目默认使用 v3；历史 v1、v2 项目仍可按已保存的 `templateVersion` 读取和渲染，目录保留历史兼容入口，由后端归档策略负责下架旧版本而不是静默改写历史项目。创建或重新编排时，后端从同一份版本化目录生成固定镜头，文本导演不会被调用；用户仍可以填写真实故事、上传人物素材和修改片尾寄语。章节之间允许换装，单个镜头内禁止变脸和变形。模板版本与镜头数量、帧数、时长、画幅不一致时，后端拒绝请求。

## Agent 创作

Agent 入口保留现有流程：用户选择场景、填写故事和拍摄要求，导演 Agent 生成导演方案、章节、造型与分镜。Agent 可以根据资料改变镜头数量和节奏，之后仍能在工作台修改单镜头或局部重做。

这些方式共用账号、项目归属、报价、额度冻结与视频生成基础设施。已编排项目按后端计划计算数量；一键生成尚未编排的项目按报价规则估算，具体见 [系统架构](architecture.md)。固定模板确定镜头结构，故事模板确定制作方法，Agent 根据资料设计整部影片。
