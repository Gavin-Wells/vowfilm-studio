# 电商广告 v3：10–60 秒分镜与生成分组

从 `/new` 的「带货快创」进入，填写商品事实、可选的逐字口播和声音方向，即可一键生成。商品图、人物图和场景图均可选；没有图片时使用文字设定，不生成虚假的图片引用。带货快创默认 30 秒、9:16；电商 Agent 默认 15 秒。

## 原版来源与适配

来源为用户提供的 `ad-video-prompt-v3.zip`，归档 SHA-256：`73a42c493c895b4c69b064233d3bdead526a145dfc704621b550fbb4d002921c`。

原始 `SKILL.md`、`references/ecommerce.md`、`references/patterns.md` 与 agent 元数据保存在 `server/internal/advertising/prompts/`，文件摘要在 `source.json`。三份规则全文嵌入系统指令，`advertising.Version()` 按原文共同计算。业务适配与 JSON 契约位于 `advertising/prompt.go`，不修改原版文件。

## 生成链路

1. 用户商品事实、自定义要求、逐字口播、声音设定和实际参考图顺序进入文本模型。`direct-storyboard` 契约要求输出细分镜，建议每镜 2–6 秒，所有时长之和等于工程时长。
2. Go 校验分镜、图像引用和总时长，将连续镜头按当前模型单次上限合并。当前适配对 H3 使用 15 秒，对 Seedance 使用 30 秒，未知模型使用 15 秒；配置在 `video_model.go`。
3. 每组只由组首镜提交一次视频任务。`GenerateGroup` 连接组内分镜，`GenerateUnit` 标识首镜，`GenerateSeconds` 保存实际请求时长；一个组内的分镜共享同一视频结果。
4. 多组工程先生成并固定第一组的人物参考，其余组在并发上限内生成。参考图用途与编号沿用实际提交顺序，不将文件名视作已识别的画面内容。
5. 单组默认保留源 MP4，多组由 FFmpeg 拼接画面和原生声音。不另加器乐配乐；明确填写片尾文字时才渲染后期覆盖。多组拼接会重新编码，不能视作逐字节保留源音轨。

工程记录 `generationMode=commerce-direct-{时长}s-v3` 和 `promptPolicy`，原 15 秒模式仍可识别。旧版或时长不匹配的分镜需重新编排；不会静默改成当前版本并提交。非电商场景使用独立工作流。

## 参数与计费

- 服务端接受 10–60 秒整数，界面提供每 5 秒一个选项；目标时长与供应商实际输出时长分别看待。
- 编排按一次规划动作报价；生成按当前价格配置的次、任务、秒或生成组计算。已有分镜时按生成组数计算；未编排的一键请求按工程时长和模型单次上限估算。
- 局部重做、生成预算和幂等恢复沿用工程任务机制，已完成片段及远端任务 ID 会保留；分镜数量不等于供应商任务数量。
- 所有付费动作继续经过项目权限、报价指纹、额度预留、成功结算和失败释放。

上传音乐不作为电商音频参考，也不会替换模型原生声音。没有实际绑定的 `<图片N>` 或 `<音频N>` 在提交前报错。口型、逐字台词、商品结构、跨组人物一致性及实际片长仍需播放验收；媒体可以解码不代表这些内容已验收通过。

| 文件                                                | 职责                                   |

以上后端路径相对 `server/internal/`。常规 `go -C server test ./...` 包含原版规则完整性、分镜与打包、不同模型上限、身份参考、音频处理和计费测试。网络测试使用模拟服务，不产生供应商费用。

`TestLiveCommerceVideo`、其他 live/复刻用例仅在显式环境开关下调用供应商。历史真实样片为 15 秒虚构收纳盒，分别位于 `deliverables/commerce-prompt-test/` 和 `deliverables/commerce-prompt-v3-test/`。这不能证明所有 10–60 秒规格、全部模型或多组组合都已完成真实验收。常规提交检查不运行付费用例。
